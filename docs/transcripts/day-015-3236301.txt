Alex: Think of those checks like tie-out tests in an audit. They do not grade quality, but they prove the model hit the baseline floor. What is step two?
Jordan: Create a configuration file. You need the absolute file paths to your Claude Code and Codex executables, plus your Gemini model ID and its token rates. Do not rely on standard terminal shortcuts here, because background schedulers run without your normal user environment. 
Alex: Which brings us to the script itself. We are building this with standard Python libraries. No external packages. Walk us through how it talks to all three tools safely.
Jordan: It runs Claude headlessly with tool permissions stripped so it cannot edit files or browse the web. Codex runs inside an isolated, read-only sandbox. And Gemini gets a direct API request using an environment key. All three take their input through standard input so weird punctuation never breaks your command line.
Alex: And when it finishes the run, what does it produce?
Jordan: First, it saves the raw response from each model into a dated evidence folder. Second, it calculates the runtime, tokens, cost, and a short SHA-256 fingerprint of the output text. Then it appends everything into a ledger spreadsheet with a blank column for reviewer initials. If at least one call works, it drops a timestamp into a heartbeat text file.
Alex: That leads straight to our first checkpoint. When you trigger the script manually from your terminal, what should you see?
Jordan: Your ledger file should immediately show nine fresh rows: three tools times three tasks. You should see nine corresponding text files in your evidence folder, and that heartbeat file sitting on your disk with the current time. 
Alex: And do not just assume a passing score means perfection. What is the controller review step?
Jordan: Open the ledger. If a task says two out of two checks passed, open the matching text file in your evidence folder. Did the model identify the dollar variance as favorable for the actual right reason? Once verified, you put your initials in the ledger. The person who builds the bench should not be the sole judge of whether the output is correct.
Alex: Once the manual run is clean, step four is scheduling it. We set a weekly recurring job in Windows Task Scheduler to run early Friday morning, completely silent, with no interactive popups.
Jordan: Run a forced test through the scheduler to verify. Your checkpoint is nine more rows appearing in the ledger and the scheduled task exiting with a clean zero status code. Then point your system watchdog to that heartbeat file with an eight-day expiration. If all calls crash, no heartbeat writes, and your alarm triggers.
Alex: Let's talk about where this breaks. What are the big three tripwires?
Jordan: First, it runs fine in your terminal but fails in Task Scheduler. That almost always means you skipped using full executable paths, or your API key is missing from system environment variables. Second, authentication dropouts or retired models. You will see error messages or 404s in the ledger instead of token counts. Third, brittle checks. A model might say "unfavorable", and your check flags it as a pass because it contained the word "favorable". 
Alex: Easy fix for that: tighten your check patterns with strict word boundaries. So, what counts as done?
Jordan: Done means your scheduled task runs unattended, logs nine fresh rows to your ledger without prompts, and writes the heartbeat.
