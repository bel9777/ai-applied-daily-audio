Jordan: Let's talk about what just happened with Gemini. Google shut down several preview text-to-speech models in mid-November. If you were calling one of those preview endpoints, it is completely gone. The good news is the stable versions, Gemini 3.8 Flash TTS and Flash-Lite, are officially out and ready for production.
Alex: So Brian's automated farm audio clips could have died instantly if he was still pointing at that preview model. What's the right way to protect these loops?
Jordan: Treat your model ID like a bank account number in a payment run: it is master data, not code. You set up a simple three-step fail-safe. First, a central registry file that maps each job to a primary model, an optional fallback, and a voice. Second, a free preflight call that pings the model endpoint. If that returns a four-oh-four, the model is gone, so stop before spending money.
Alex: And if that preflight check passes, you run the real audio call?
Jordan: Almost. Step three is the canary. You fire a tiny, two-word test call before touching the real job, and verify you got back a healthy payload of audio bytes. If that canary succeeds on the primary model, you run the job and write a normal heartbeat. If it has to drop to the fallback model, like Flash-Lite, you write a warning line to your daily watchdog. And if both fail, the job halts, raises a full alert, and skips the heartbeat so your dead-man's switch wakes you up.
Alex: That way, even if Park View Farm drops to the lighter voice for delivery reminders, Brian knows immediately. And if audio totally fails, the script can still send the raw text email instead of breaking the whole customer loop.
Jordan: Exactly. But that brings us to the biggest gotcha: silent fallbacks. A fallback changes your tone, quality, and cost. If your script switches models without telling you, it is just as bad as failing silently. And in serious business contexts, like finance or lease reconciliation, you should never have an automatic fallback at all. Switching models without testing and approval violates internal controls. In finance, the job must fail closed and page an owner.
Alex: Makes sense. Also, keep the API key out of that registry file. Keep it in an environment variable or your credential manager.
Jordan: Absolutely. Let's do a quick check. First question: what if the canary gets a two hundred OK status from Google, but the returned audio is just a fraction of a second of silence?
Alex: That counts as a failure. You do not write the heartbeat, you do not publish the file, and you trigger the alert. An API can return a success code while delivering an empty payload, so you have to validate the actual byte size.
Jordan: Spot on. Second question: your farm delivery script ran on Flash-Lite for six straight days and nobody noticed. What part of the design failed?
Alex: The alerting failed. The fallback did its job by keeping audio running, but it stayed silent. It should have flagged a degraded warning on the daily watchdog email so Brian knew the primary model was down.
